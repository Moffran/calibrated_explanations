# v1.1.0 Plan

> **Release version:** `1.1.0`
> **Development version:** `1.1.0-dev`
> **Status:** Active
> **Theme:** Semantic correctness, contract consolidation and API hardening
> **Scope review:** 2026-11-25

## Outcome

Deliver self-describing ADR-005 explanation payloads, compatible offline narration,
canonical ranking (ADR-042), truthful unbounded one-sided CPS endpoints,
strict configuration-token validation, explicit typed explanation parameters,
and narrowly scoped sensitive-value redaction. Document the distinction between
scalar threshold-event calibration and a coherent multi-threshold CDF without
changing scalar prediction mathematics. Do not freeze an additional narrative
contract without evidence that the existing payload is insufficient for a concrete
consumer. Preserve existing stable APIs and avoid new runtime dependencies.

not planned: no narrative provider family, registry, dispatch, tuning API, or
prose verification. T14 (#205) is unscheduled backlog: only reconsider a small
validation command for discovered plugins on demonstrated author need. T15
(#203) is not planned: retain the root `transform_to_numeric` compatibility
export and the utils import; prefer wrapper preprocessing in new guidance
(ADR-009 scope revision).

- Rewriting the offline narrator over NarrativeSpec or introducing a new provider.
- Public ranking results, ranking plugins, or new ranking/search algorithms.
- A plugin package/path validation subsystem or versioned diagnostics format.
- A new CDF query/result contract, joint threshold calibration research, or
  sorting/clipping/isotonic postprocessing of independently calibrated outputs.
- New dependencies, explanation types, modalities or default-enabled cache/parallel.

## Dependencies and implementation boundaries

- T1 (done 2026-11-25) decided removal: ADR-041 D2 now forbids a separate
  narrative fact record without a demonstrated consumer, and ADR-042 D15 is
  amended accordingly. No supported consumer, capability claim, release tag
  (v1.0.0-v1.0.2) or downstream code uses `NarrativeSpec`; every field is in
  the payload or a one-line derivation, and since T10 open endpoints are
  serialized as `-inf`/`inf`, so no bounded flags are needed. No adapter is
  retained, so the adapter branch of #229/#230 no longer applies.
- T2 and T6 stay complete; verify payload round-trip and offline narration after
  the T3/T4 change. Existing template narration remains unchanged except for
  intentional ADR-042 selection, filtering and ordering changes.
- T3/T4 remove `explanations/narrative_spec.py`, the `explanations` package
  exports, the `docs/api/calibrated_explainer.md` "Narrative facts" section,
  the `to_narrative.md` spec section, the spec wording in the unreleased
  `CHANGELOG.md` entries (keep the `narrative_context` and ADR-042 text), the
  `build_narrative_spec` assertion in `tests/capabilities/test_narrative_contracts.py`
  and the `_ranking.py` docstring mention. In `test_narrative_spec.py`, keep the
  `narrative_context` tests (#228), delete spec-only tests, and move any check
  still covering remaining behaviour (unbounded endpoints, percentile-scope
  containment, ADR-042 order) onto the payload, serialization or narration
  where not already covered. Do not add a replacement validator or ranking API.
- T9 has source and test implementation on main; verify canonical top-k and
  ties across normal factual, FAST, multiclass and alternative consumers,
  conjunction selection and narrative/plot parity. Preserve documented legacy
  exceptions and deprecations. Do not add public ranking APIs. Adapt the T9/T10
  task verification lists after T3/T4 if spec-specific files are removed.
- T10 preserves percentile-aware invariants and JSON round-trip. Only supported
  plot paths must render open endpoints correctly; document existing unsupported
  one-sided uncertainty plot modes, rather than broadening plotting scope.
- T11/T12 retain existing behavior and evidence; no new abstractions.
- T13 reuse/promote the existing redaction utility in a dependency-safe location.
  Redact recursively, including nested sequences and schema-marked values, before
  payload return/logging; replace raw exception messages in governance events
  with controlled reason codes/safe metadata. Test actual emitted payloads and
  log records with sentinel secrets. Preserve safe diagnostic fields and document
  the limits; no generic PII detector, secrets manager or policy framework.
- T16 amend ADR-021, RTD and relevant API docs: scalar event predictions do not
  jointly guarantee monotonicity. Existing empirical evidence is diagnostic;
  further experiments and any new CDF method are independent research, not a
  release dependency. No calibration algorithm/API changes.

## Release-specific gates

- ADR-041 and ADR-042 D15 reflect the T1 decision (done); no `NarrativeSpec`,
  `build_narrative_spec` or `NARRATIVE_SPEC_VERSION` remains in `src/`, `docs/`,
  `tests/`, `CHANGELOG.md` or the task-verification lists (T3/T4).
- Additive narrative context round-trips; legacy payloads remain valid; existing
  offline public formats work without network or new runtime dependencies (T2/T6).
- Canonical rankings and deliberate compatibility exceptions are verified across
  consumers; ordering/selection changes and unbounded endpoints have migration
  notes (T9/T10). Existing deprecations follow ADR-011/ADR-020.
- Serialized open endpoints round-trip and supported plot paths render; unsupported
  modes are documented (T10).
- T11/T12 behavior and relevant prior regression checks remain intact.
- Known sensitive values are absent from returned governance event payloads and
  actual emitted logs; ordinary safe metadata remains available (T13).
- ADR-021 and public docs state the scalar-versus-CDF limitation. No scalar
  numerical/API change is introduced by T16; no new research execution required.
- `make capability-chain-check` passes. Standard repository gates are owned by
  `release.md` and `make release-preflight`; do not create new generic gates.

## Release decision

`Not ready` — T1, T2, T6, T10, T11 and T12 are complete. T3/T4 implement the
T1 removal; T9 needs final verification; T13 and documentation-only T16 remain
outstanding.

T1 evidence (2026-11-25): consumer inventory on `main` (narrator, narrative plot
plugin, plots, conjunctions, serialization, capability claims/requirements),
release tags v1.0.0-v1.0.2 and GitHub code search found no consumer of
`NarrativeSpec`/`build_narrative_spec` besides its own tests, one capability-test
assertion and two docs sections. A regression `to_json()` with
`low_high_percentiles=(-inf, 90)` serializes the open prediction and weight
endpoints as `"-inf"`/`"inf"`. ADR-041 is revised (D2: no separate fact record;
Alternatives 2-3 record the rejected keep/reduce options); ADR-042 D15 is
amended; `docs/schema_v1.md` no longer calls open endpoints placeholders.
#229/#230 acceptance criteria are narrowed to removal. Documentation-only change;
no source or tests changed.

T12 evidence (2026-11-23): `multi_labels_enabled` and `interval_summary` are
explicit keyword-only parameters on the direct and wrapper factual/alternative
methods, validated once at `CalibratedExplainer`; the orchestrator and the
plugin request receive canonical values (ADR-038 2026-11-23 addendum).
`python scripts/local_checks.py --profile task --task 12` and
`make local-checks-pr` pass (5052 passed, 2 skipped).

`ConfigurationError` with `env_var`/`token` details on the parser, builder and
plain-constructor paths; the #219 warning-policy entry is removed.
