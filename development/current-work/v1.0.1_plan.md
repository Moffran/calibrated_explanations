## T4) Wrapper auto-encoding for mixed-type data

### T4.1 Status assessment

Completed 2026-09-11. The built-in `auto_encode='auto'` path now leaves
numeric columns unchanged, encodes categorical columns deterministically,
supports explicit categorical feature overrides, and applies the configured
missing-value policy for categorical inputs.

Reopened 2026-09-22: the encoder fix did not reach the public entry point.
`WrapCalibratedExplainer.fit()`/`calibrate()` only called `_pre_fit_preprocess`
when a user preprocessor was set, so the default `auto_encode='auto'` wrapper
still failed on mixed-type DataFrames. The prior tests exercised the helper
directly or supplied a preprocessor. Fixed by routing through
`_should_pre_fit_preprocess` (non-numeric input or configured
`categorical_features`), with end-to-end coverage added below.

### T4.2 Verification checklist

- [x] `tests/unit/core/test_builtin_encoder.py` covers mixed-type passthrough,
  explicit categorical overrides, and missing-value policy failures.

  auto-encoding preserves numeric columns and respects the configured

- [x] `tests/unit/core/test_config_management_contract.py` verifies the new
  `ExplainerConfig`/`ExplainerBuilder` preprocessing fields are exposed and

## T5) Explicit cache and parallel initialization failures

### T5.1 Status assessment

Completed 2026-09-21. An explicitly requested cache or parallel executor that
cannot be initialized now fails closed with `ConfigurationError` from
`ExplainerBuilder.build_config()` or `WrapCalibratedExplainer.from_config()`,
with `details` naming the `capability`, failing `source` and `cause`.
Non-numeric `CE_CACHE`/`CE_PARALLEL` values raise `ConfigurationError` on both
the builder and plain constructor paths. The perf factory records activation
per capability (`config`, `env`, `disabled_by_env`, or `None`). Retained ADR-004
fallbacks (pool start-up failure, `force_serial` recovery, joblib requested
but missing) emit `UserWarning` plus INFO and are registered as user-visible in
`check_warning_policy.py`; the DEBUG-only `wrap_from_config_perf_primitives`
exemption was removed. The minimal cache-backend notice now fires once per
process, only when an enabled cache is built (registered exemption).

Maintainer decisions: keep ADR-004 graceful degradation for pool start-up
failure; raise in `build_config()`. Adjacent defects split out: #218 (enabled
parallel with the default `auto` strategy silently auto-selects a backend),
#219 (unrecognised `CE_PARALLEL`/`CE_CACHE` tokens are ignored), #220
(`CE_CACHE` is only honoured on the builder/config path).

- **T4 defect found and fixed** (commit `0946bddb`, "fix: ensure default
  WrapCalibratedExplainer auto-encodes mixed-type input and raises
  ValidationError for unsupported cases"): `fit()`/`calibrate()` only routed
  input through `_pre_fit_preprocess()` when `self._preprocessor is not
  None`, but the built-in ADR-009 encoder only activates *inside*
  `_pre_fit_preprocess()` when `self._preprocessor is None`. The built-in
  encoder was therefore unreachable through the public API for the default
  (no explicit preprocessor) configuration — the exact scenario #202 was
  meant to fix; a mixed-type `DataFrame` passed to `wrapper.fit()` reached
  sklearn with raw string columns. Missed by T4's original verification
  because every T4 unit test called the internal `pre_fit_preprocess()`
  helper directly instead of exercising `wrapper.fit()`. Fixed via a new
  `_should_pre_fit_preprocess()` gate plus 4 new end-to-end integration

  all 88 tests in T4's original verification-checklist files still pass.
