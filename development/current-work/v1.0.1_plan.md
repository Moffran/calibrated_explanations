> **Development version:** `1.0.1-dev`
> **Status:** Active
> **Theme:** Post-v1.0 stabilisation

## Outcome

Confirms that the v1.0.0 GA quality and performance baselines remain clean,
completes the release-planning simplification, and delivers narrowly scoped
post-GA correctness fixes for documented wrapper preprocessing and explicitly
requested cache/parallel initialization. The release adds no new public API or
plugin category and does not enable cache or parallel execution by default.

## Excluded

- New public API or plugin categories.
- Caching/parallel on-by-default graduation; both remain explicitly opt-in.
- Deprecation or removal of the root `transform_to_numeric` export; tracked by
  #203 for a future minor-release deprecation cycle.
- Ranking-semantics consolidation and plugin-author diagnostics unless separately
  assigned to this milestone.
- Broad preprocessing, cache, parallel, or plugin architecture redesign beyond
  the defects defined in the included issues.

## Dependencies

- T4 depends on completion of T1 and the preprocessing replacement defined in #202.
- T6 runs only after T1-T5 are Done or explicitly removed from the milestone by
  maintainer decision.

## Release-specific gates

- Docstring coverage and Standard-001 nomenclature checks pass on the release
  commit (T2).
- Caching/parallel telemetry shows no regression against the RC/GA baseline
  (T3).
- Mixed-type wrapper workflows pass classification and regression integration
  tests without altering purely numeric inputs (T4).
- Explicitly requested cache or parallel initialization cannot silently
  degrade, while sequential defaults and opt-in behavior remain unchanged
  (T5).
- Standard repository gates (tests, lint, docs build, version alignment) are
  owned by `release.md` and `make release-preflight`; not repeated here.
