# v1.0.2 Plan

> **Release version:** `1.0.2`
> **Development version:** `1.0.2-dev`
> **Status:** Active
> **Theme:** Runtime configuration contract

## Outcome

Makes the `CE_PARALLEL` / `CE_CACHE` environment directives and the
`perf_parallel` builder behave as ADR-003, ADR-004 and the runtime how-to pages
already document: an enabled executor with the removed `auto` strategy fails
fast, unrecognised tokens are surfaced instead of dropped, and `CE_CACHE=on`
works on the plain `WrapCalibratedExplainer` path. It also closes an HTML
injection defect in narrative output, corrects the narrative capability claim,
and records the canonical ranking contract as an accepted ADR so the ranking
consolidation (#204) can be implemented in v1.1.0. The release adds no new
public API or plugin category and does not enable cache or parallel execution
by default.

Release handoff (`make release-preflight` -> `make release-finalize` ->
maintainer steps 11-13 -> `make release-postcommit`, per `release.md`) is the
publication procedure itself, not a deliverable, so it is intentionally not a
gated row in this table: `make release-preflight`'s readiness guard requires
every row above to read `Done` before it will run, and a self-referential
"publish" row could never satisfy that check (this broke v1.0.1's first
release-preflight run; see `development/finished-work/v1.0.1_plan.md`). It
runs once T1-T6 all read `Done`.

## Excluded

- New public API or plugin categories.
- Caching/parallel on-by-default graduation; both remain explicitly opt-in.
- Raising `ConfigurationError` for unrecognised `CE_*` tokens; tracked by #225
  for v1.1.0.
- Implementing the ranking contract or changing any rule/feature ordering;
  tracked by #204 for v1.1.0.
- ADR-041 narrative provider plugin family; targeted at v1.1.0.
- Interval-calibration update consolidation (#208); pending maintainer
  investigation and not assigned to a milestone.

## Dependencies

- T1, T2 and T3 touch the same parsers and perf-factory paths
  (`parallel/parallel.py`, `cache/cache.py`, `api/config.py`,
  `core/calibrated_explainer.py`); land them sequentially in ID order to avoid
  conflicting changes.
- T2's warning text references the v1.1.0 escalation in #225.
- Release handoff (see `## Included work`) runs only after T1-T6 are Done.

## Release-specific gates

- With `CE_PARALLEL` and `CE_CACHE` unset, behaviour is unchanged: sequential
  execution, no cache, and no new warnings on the default `fit` → `calibrate`
  → `explain_*` lifecycle (T1-T3).
- The v1.0.1 cache/parallel telemetry smoke still matches the RC baseline
  (`hits=1, misses=1`; `strategy="threads", workers=2`) (T1-T3).
- The new T2 warning is registered in `scripts/quality/check_warning_policy.py`
  with zero failures.
- `make capability-chain-check` passes (T5).
- The ranking ADR is `Accepted` and existing ranking/ordering tests pass
  unchanged (T6).
- Standard repository gates (tests, lint, docs build, version alignment) are
  owned by `release.md` and `make release-preflight`; not repeated here.
